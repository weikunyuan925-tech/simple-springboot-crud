# 依赖升级与安全复测报告

**项目名称：** simple-springboot-crud

**升级分支：** dependency-upgrade
**升级前版本：** Spring Boot 3.2.0
**升级后版本：** Spring Boot 4.1.3

**报告类型：** 依赖升级、兼容性验证与安全复测

## 一、升级背景与目标

本项目此前基于 Spring Boot 3.2.0 开发，并已完成基础安全审计及自动化安全测试。

为了进一步提升项目依赖安全性、验证 Spring Boot 大版本升级的兼容性，并完成 Jackson 2 到 Jackson 3 的迁移，本次开展依赖升级与安全复测工作。

本次升级主要目标：

1. 将 Spring Boot 从 3.2.0 升级至 4.1.3。
2. 将 Spring Boot Web 层的 JSON 处理迁移至 Jackson 3。
3. 解决 Spring Boot 4 测试依赖及测试包结构变化带来的兼容性问题。
4. 复测此前发现并整改的 F16：JSON 类型强制转换问题。
5. 检查日期序列化行为是否符合预期。
6. 使用 OWASP Dependency-Check 重新扫描项目依赖。
7. 分析 Jackson 2 与 Jackson 3 并存的原因，确认是否存在不必要的依赖。

### 3.1 Spring Boot 升级


编译成功。

### 3.2 Jackson 3 迁移

Spring Boot 4 使用 Jackson 3。

原有 Jackson 2 包名：

```
com.fasterxml.jackson.databind
```

迁移后的 Jackson 3 包名：

```
tools.jackson.databind
```

针对项目中的 JSON 处理配置和测试代码进行了相应迁移。

主要调整：

1. Jackson 配置类迁移至 Jackson 3 API。
2. `ObjectMapper` 导入路径迁移。
3. `JsonNode` 等相关类型迁移。
4. 保留原 F16 严格字符串类型校验逻辑。

Jackson 3 的配置继续对以下输入类型执行拒绝策略：

- Integer
- Float
- Boolean
- Array
- Object

对应的配置通过 `JsonMapperBuilderCustomizer` 和 Jackson 3 的 Coercion API 实现。

### 3.3 Spring Boot 4 测试依赖调整

Spring Boot 4 对测试依赖进行了模块化拆分。

| spring-boot-starter-data-jpa-test | JPA 测试             |

同时完成测试代码迁移：

| `@WebMvcTest`           | `org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest` |
| `@AutoConfigureMockMvc` | `org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc` |

### 3.4 日期序列化配置调整

原项目使用 Jackson 2 的配置：

```
spring.jackson.serialization.write-dates-as-timestamps=false
```

升级后发现该旧配置不能直接按照原方式绑定到 Jackson 3。

因此暂时注释该配置，并通过接口实际响应验证日期序列化结果。

实际响应中的日期格式为：

```
2026-11-25T22:57:25.163053
```

结果为 ISO-8601 字符串，而非数字时间戳。

当前行为符合预期，无需额外配置。

## 六、Jackson 2 与 Jackson 3 并存分析

升级后检查 Maven 依赖树，发现项目同时存在 Jackson 2 和 Jackson 3。

### 6.1 Jackson 3 依赖来源

依赖路径：

```
spring-boot-starter-web`
→ `spring-boot-starter-jackson`
→ `spring-boot-jackson`
→ `tools.jackson.core:jackson-databind:3.1.8`
→ `tools.jackson.core:jackson-core:3.1.8
```

这是 Spring Boot 4 的 Jackson 3 依赖链。

### 6.2 Jackson 2 依赖来源

依赖路径：

```
jjwt-jackson:0.13.0`
→ `com.fasterxml.jackson.core:jackson-databind:2.21.8`
→ `jackson-annotations:2.21`
→ `jackson-core:2.21.8
```

确认 Jackson 2 是由 JJWT 的 JSON 适配模块引入，而不是 Spring Boot Web 层引入。

### 6.3 风险判断

目前项目使用两套 Jackson：

- Spring MVC 的 JSON 请求与响应处理使用 Jackson 3。
- JJWT 的 Jackson JSON 适配模块使用 Jackson 2。

两套依赖使用不同的 Java 包名，可以在同一应用中共存。

因此：

1. Jackson 2 与 Jackson 3 并存本身不代表迁移失败。
2. 不应直接排除 `jjwt-jackson` 的 Jackson 2 依赖。
3. 当前没有证据表明这两套依赖造成了运行时冲突。
4. 后续如果有彻底移除 Jackson 2 的需求，可以评估替换 JWT JSON 适配器，但不是本次必须整改的事项。

**当前处理结论：保留 JJWT 0.13.0 的现有依赖配置，不进行强制排除。**
