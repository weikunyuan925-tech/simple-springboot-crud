## 2. 阶段目标

本阶段在前期安全审计与漏洞整改工作的基础上，将部分安全检查转化为可重复执行的自动化测试。

主要目标：

1. 验证关键安全接口的认证要求。
2. 验证 JWT 的有效性、签名及过期校验。
3. 验证不同用户之间的资料访问隔离。
4. 验证资料创建、查询、修改和删除过程中的对象级授权。
5. 建立可重复执行的安全回归测试集，降低后续代码变更引入安全回归的风险。

## 3. 自动化测试体系

本阶段建立了 T1～T4 四组自动化安全测试。

| 测试编号 | 测试主题                   | 主要验证内容                                                 |
| -------- | -------------------------- | ------------------------------------------------------------ |
| T1       | 安全回归测试基线           | 匿名访问控制、健康检查、无效 JWT、登录认证                   |
| T2       | JWT 身份认证测试           | 正确账号密码登录、有效 JWT 访问受保护接口、用户身份认证      |
| T3       | JWT 异常与过期测试         | 伪造 Token、篡改 Payload、篡改 Signature、过期 Token、错误 Authorization 格式 |
| T4       | JWT 权限控制与越权访问测试 | 跨用户读取、列表、邮箱查询、姓名搜索、修改、删除及伪造 ownerId |

## 5. 重点安全测试成果

### 5.1 身份认证控制

验证匿名用户无法访问受保护的用户资料接口，正确账号密码能够完成登录并获取 JWT。

### 5.2 JWT 安全校验

验证以下异常 Token 均被系统拒绝：

- 完全伪造的 Token。
- Payload 被篡改的 Token。
- Signature 被篡改的 Token。
- 已经过期但签名合法的 Token。
- 使用错误 Authorization 格式提交的请求。

本轮对应异常场景均返回 HTTP 401。

### 5.3 对象级授权与越权访问

通过创建两个独立普通用户，验证用户之间的数据隔离。

本轮覆盖：

- 跨用户读取资料。
- 跨用户获取资料列表。
- 跨用户邮箱查询。
- 跨用户姓名搜索。
- 跨用户修改资料。
- 跨用户删除资料。
- 创建资料时伪造 ownerId。

上述测试均达到预期结果。

## 6. 自动化测试环境

测试采用独立的 `test` Profile 和 H2 内存数据库，避免使用生产数据库执行安全测试。

测试配置包括：

- 独立的测试数据库。
- 测试专用 JWT 密钥。
- 测试专用 JWT 有效期。
- 关闭 H2 Console。
- 禁用测试数据初始化，按测试需要创建数据。
- 通过 Spring Boot Test 和 MockMvc 执行集成测试。

## 8. 阶段结论

本阶段完成了从人工安全验证向自动化安全回归测试的初步转化。

建立了覆盖身份认证、JWT 异常处理及对象级授权的自动化测试体系。

T1～T4 集成回归测试共统计 8 个测试类、48 项测试用例，失败 0 项、错误 0 项、跳过 0 项，通过率为 100%。

本阶段测试结果表明：在当前测试环境和已覆盖场景下，相关安全控制均达到预期。

需要说明的是，自动化测试通过不等于系统不存在其他安全漏洞。尚未覆盖的安全领域仍需通过后续专项测试持续验证。

## 9. 后续改进方向

建议下一阶段继续开展以下工作：

1. **角色权限测试（RBAC）**：在增加管理员专属业务接口后，验证 USER 与 ADMIN 的权限边界。
2. **并发安全测试**：使用 JMeter 验证并发登录、并发访问及业务操作的一致性。
3. **接口滥用测试**：验证频率限制、暴力尝试防护和批量请求风险。
4. **输入验证专项测试**：持续验证参数边界、JSON 类型、搜索条件及异常处理。
5. **自动化执行集成**：考虑将安全测试接入 GitHub Actions，实现代码提交后的自动回归。
