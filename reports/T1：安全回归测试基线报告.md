# T1：安全回归测试基线报告

## 1. 测试目标

建立独立的安全回归测试类，验证 Spring Security 和 JWT 认证机制的基本安全边界。

通过自动化测试验证：

- 匿名用户无法访问受保护接口。
- 无效 JWT 无法通过身份认证。
- 公开接口允许匿名访问。
- 用户能够通过公开登录接口完成身份验证并取得 JWT。

## 5. 关键测试验证

### SEC-01：匿名访问用户列表

验证未携带 Authorization 请求头的匿名请求，无法访问用户列表。

测试结果：401 Unauthorized。

### SEC-02：匿名访问用户详情

验证匿名用户无法通过修改 URL 中的用户 ID 访问受保护接口。

测试结果：401 Unauthorized。

### SEC-03：匿名访问健康检查

验证健康检查接口按照 SecurityConfig 的公开接口规则正常放行。

测试结果：200 OK。

### SEC-04：无效 JWT 访问用户列表

验证携带格式无效的 JWT 时，系统不能建立有效的认证上下文。

测试结果：401 Unauthorized。

### SEC-05：公开登录接口

测试过程：

1. 在测试数据库创建专用测试账号。
2. 使用 PasswordEncoder 对密码进行 BCrypt 加密。
3. 不携带 Authorization 请求头。
4. 调用 POST /api/auth/login。
5. 验证返回 HTTP 200。
6. 验证响应包含非空 JWT、Bearer 类型及有效期。

测试结果：登录成功，服务器正常签发 JWT。

## 7. 测试结论

本轮 T1 安全回归测试已完成。

验证结果表明，当前测试配置下：

1. 用户列表和用户详情受到身份认证保护。
2. 无效 JWT 无法通过身份认证。
3. 健康检查接口允许匿名访问。
4. 登录接口允许匿名调用。
5. 正确账号密码能够完成登录并取得 JWT。

测试环境已使用独立 H2 数据库及测试专用 JWT 配置，避免依赖开发环境数据库和账号初始化配置。

## 8. 当前测试覆盖范围及不足

本轮测试尚未覆盖：

- 有效 JWT 访问受保护接口。
- JWT 过期验证。
- JWT 签名篡改验证。
- 用户 A、用户 B 的对象级访问控制。
- 不同角色之间的权限隔离。

因此，本轮通过仅代表基础安全边界测试通过，不代表整个 JWT 认证与授权机制已经全面验证。
